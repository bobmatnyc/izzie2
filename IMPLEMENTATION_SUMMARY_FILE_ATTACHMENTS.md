# File Attachments Feature Implementation Summary

## Overview
Implemented the **inbound file transfer feature** for Izzie, enabling users to send files via Telegram that are automatically uploaded to Google Drive in an "izzie/attachments" folder.

**Date**: 2026-02-14
**Status**: ✅ Implementation Complete (Ready for Testing)
**Phase**: Phase 1 - Inbound File Transfers (Telegram → Drive)

---

## What Was Implemented

### 1. Database Schema
**File**: `src/lib/db/schema.ts`

Added `fileAttachments` table with the following structure:
- Transfer tracking (direction, status, timestamps)
- File metadata (name, MIME type, size)
- Google Drive references (fileId, folderId, webViewLink)
- Telegram references (fileId, chatId, messageId)
- Session linking (optional chatSessionId)
- Error tracking (errorMessage)
- Extensible metadata (JSONB)

**Migration**: `drizzle/migrations/0034_add_file_attachments.sql`
- Auto-generated by Drizzle ORM
- Includes comprehensive indexes for performance
- Column comments for documentation

### 2. Core Services

#### a. **TelegramFileService** (`src/lib/services/telegram-file.service.ts`)
Handles Telegram Bot API file operations:
- `getFileInfo(fileId)` - Get file metadata from Telegram
- `downloadFile(fileId)` - Download file as Buffer
- `sendDocument(options)` - Send file to Telegram chat
- `validateFileSize(size)` - Check against 50MB Telegram limit

**Key Features**:
- Direct Telegram Bot API integration
- File size validation (50MB limit)
- Multipart form data support for uploads

#### b. **FileUploadService** (`src/lib/services/file-upload.service.ts`)
Manages Google Drive uploads:
- `uploadFile(options)` - Upload file to Drive
- `ensureAttachmentsFolder()` - Create "izzie/attachments" folder structure
- `validateFileSize(size)` - Check against 100MB Drive limit
- `getAttachmentsFolderId()` - Retrieve existing folder ID

**Key Features**:
- Automatic folder creation (izzie → attachments)
- Folder search and caching
- Readable stream support for large files
- Size validation (100MB limit)

#### c. **FileAttachmentService** (`src/lib/services/file-attachment.service.ts`)
Orchestrates the complete file transfer workflow:
- `receiveFileFromUser(options)` - Complete inbound transfer (Telegram → Drive)
- `sendFileToUser(options)` - Complete outbound transfer (Drive → Telegram)
- `validateFileType()` - Security validation (MIME types, blocked extensions)
- `getUserFileAttachments()` - Query transfer history
- `checkRateLimit()` - Enforce 10 transfers/hour limit

**Key Features**:
- Status tracking (pending → processing → completed/failed)
- Comprehensive error handling
- Security validation (blocked extensions: .exe, .bat, .sh, etc.)
- Allowed MIME types (documents, images, archives)
- Rate limiting (10 transfers per hour per user)

#### d. **FileDownloadService** (`src/lib/services/file-download.service.ts`)
Downloads files from Google Drive (already existed):
- `downloadFile(fileId)` - Download file with auto-format conversion
- `canDownload(fileId)` - Pre-check file size limits
- Automatic Google Workspace file export (Docs → plaintext, etc.)

### 3. Telegram Integration

#### a. **File Handler** (`src/lib/telegram/file-handler.ts`)
Processes incoming file messages:
- `handleDocumentMessage()` - Process document uploads
- `handlePhotoMessage()` - Process photo uploads
- OAuth token management
- User-friendly error messages
- Progress notifications

**User Experience**:
1. User sends file to Izzie via Telegram
2. Bot responds: "⏳ Uploading file to Google Drive..."
3. File is transferred in the background
4. Bot responds: "✅ File uploaded successfully! 📎 [filename] 🔗 [View in Drive]"

#### b. **Webhook Handler** (`src/app/api/telegram/webhook/route.ts`)
Modified to handle file messages:
- Detect document and photo messages
- Verify user is linked before processing
- Route to appropriate file handler
- Maintain existing text message handling

**Type Updates** (`src/lib/telegram/types.ts`):
- Added `TelegramFile` interface
- Added `TelegramDocument` interface
- Added `TelegramPhotoSize` interface
- Extended `TelegramMessage` with file fields

### 4. Security & Validation

#### File Type Security
**Blocked Extensions** (security risk):
```
.exe, .bat, .cmd, .sh, .app, .deb, .rpm, .dmg, .pkg,
.msi, .scr, .com, .pif, .vbs, .js, .jar
```

**Allowed MIME Types**:
- **Documents**: PDF, Word, Excel, PowerPoint, text files
- **Images**: JPEG, PNG, GIF, WebP, SVG
- **Archives**: ZIP, RAR, 7z, gzip, tar

#### Size Limits
- **Telegram → Drive**: 50MB (Telegram bot limit)
- **Drive → Telegram**: 50MB (Telegram bot limit)
- **Drive Uploads**: 100MB (Drive API limit)

#### Rate Limiting
- **Limit**: 10 file transfers per user per hour
- **Tracking**: Based on completed transfers in last 60 minutes
- **Error Message**: User-friendly with remaining count

## Architecture Decisions

### 1. Service Layer Pattern
Three focused services with single responsibilities:
- **TelegramFileService**: Telegram-specific operations
- **FileUploadService**: Drive-specific operations
- **FileAttachmentService**: Business logic orchestration

### 2. Status Tracking
File transfers tracked through lifecycle:
1. `pending` - Record created, transfer not started
2. `processing` - Transfer in progress
3. `completed` - Transfer successful
4. `failed` - Transfer failed (error message stored)

### 3. Folder Management
Automatic folder creation strategy:
- Root → "izzie" folder → "attachments" subfolder
- Folder search before creation (idempotent)
- Caching folder IDs for performance

### 4. Error Handling
Comprehensive error handling at each layer:
- Service layer: Detailed logging, error propagation
- Handler layer: User-friendly messages
- Database: Error messages stored for audit trail

## Usage

### For Users
1. Link Telegram account at `izzie.ai/settings`
2. Send any file to Izzie bot on Telegram
3. File automatically uploads to Google Drive
4. Receive confirmation message with Drive link

### For Developers
```typescript
import { getFileAttachmentService } from '@/lib/services/file-attachment.service';
import { getOAuth2Client } from '@/lib/google/auth';
import { getGoogleTokens } from '@/lib/auth';

// Get user's OAuth tokens
const tokens = await getGoogleTokens(userId);
const oauth2Client = await getOAuth2Client();
oauth2Client.setCredentials({
  access_token: tokens.accessToken,
  refresh_token: tokens.refreshToken,
});

// Upload file from Telegram to Drive
const service = getFileAttachmentService();
const result = await service.receiveFileFromUser({
  userId,
  telegramFileId: 'ABC123',
  telegramChatId: 123456789n,
  fileName: 'document.pdf',
  mimeType: 'application/pdf',
  fileSize: 1024000,
  driveAuth: oauth2Client,
});

console.log(result.driveWebViewLink); // Drive URL
```

## Performance Considerations

### Optimizations Implemented
1. **Folder Caching**: Search for existing folders before creation
2. **Streaming Uploads**: Use Readable streams for large files
3. **Database Indexes**: 8 indexes for fast queries
4. **Rate Limiting**: Prevent abuse and resource exhaustion
5. **Async Processing**: Non-blocking file transfers

### Scalability
- **Concurrent Transfers**: Each transfer is independent
- **Rate Limits**: Per-user limits prevent single-user abuse
- **Database**: Indexed for fast lookups at scale
- **Error Recovery**: Failed transfers don't block others

---

## Security Measures

### 1. File Type Validation
- Whitelist of allowed MIME types
- Blacklist of executable extensions
- Rejection of potentially harmful files

### 2. Size Validation
- Telegram: 50MB limit enforced
- Drive: 100MB limit enforced
- Pre-validation before download/upload

### 3. Access Control
- User must be linked (Telegram ↔ Izzie)
- OAuth tokens verified for Drive access
- User can only access their own files

### 4. Rate Limiting
- 10 transfers per user per hour
- Tracked by completed transfers
- Prevents abuse and resource exhaustion

### 5. Audit Trail
- All transfers logged in database
- Status tracking (pending → completed/failed)
- Error messages stored for debugging

## Known Limitations

### Current
1. **Outbound Not Implemented**: Drive → Telegram needs Phase 2
2. **No UI**: Transfer history not visible in web app
3. **Fixed Folder**: Always uploads to "izzie/attachments"
4. **Single Account**: Uses primary Google account only

### By Design
1. **50MB Limit**: Telegram bot API restriction
2. **10/hour Limit**: Prevents abuse
3. **Blocked Executables**: Security measure
4. **No Compression**: Files uploaded as-is
